# `kubeconfig-composer init`: сборка kubeconfig при старте shell

Дата: 2026-10-09. Статус: черновик на ревью.

## Цель

Одна строка в `.bashrc` или `.zshrc` — `eval "$(kubeconfig-composer init)"` — держит
актуальный `~/.kube/kc.yaml`, собранный из всех kubeconfig-файлов в `~/.kube`, и
экспортирует `KUBECONFIG=~/.kube/kc.yaml`. Исходные файлы не меняются и не
перемещаются.

Критерии успеха:
- Старт терминала, когда источники не менялись, занимает миллисекунды: `init` только
  читает `stat` файлов и ничего не парсит.
- Изменение, добавление или удаление источника подхватывается при следующем старте
  терминала.
- `kubectl config use-context`, `kubectx` и `kubens` не теряют результат при пересборке.
- Сбой `init` не ломает запуск shell.

Не входит в задачу: фоновый демон, слежение за файлами (inotify), поддержка fish и
PowerShell, проверка доступности кластеров при старте.

## Модель

`kc.yaml` — производный файл. Источники (файлы в `--dir`) — единственная правда.
Из `kc.yaml` переживает пересборку только состояние сессии: `current-context` и
`namespace` в контекстах. Остальные правки `kc.yaml` перезаписываются; для
инструментов, которые добавляют кластеры (`aws eks update-kubeconfig`,
`gcloud ... get-credentials`), в README рекомендуется алиас с отдельным файлом-источником:

```bash
alias eks-add='KUBECONFIG=~/.kube/aws.yaml aws eks update-kubeconfig'
```

## Интерфейс

```
kubeconfig-composer init [--dir ~/.kube] [--output ~/.kube/kc.yaml]
                         [--prefix kc] [--max-size 5] [--refresh]
```

- stdout: только `export KUBECONFIG='<абсолютный путь output>'`.
- stderr: предупреждения и ошибки. В штатном случае пусто.
- `--max-size` — порог суммарного размера источников в МБ (по умолчанию 5; 0 отключает порог).
- `--refresh` — пересобрать сейчас, порог не учитывается.
- Флаги `--dir` и `--prefix` те же, что у `merge`; интерактивных вопросов нет.

## Алгоритм

1. **Обход.** Рекурсивно по `--dir` через `stat`, без чтения содержимого. Пропускаются
   каталоги `cache` и `http-cache`, скрытые файлы и каталоги, сам `--output`. В
   отпечаток входят все остальные обычные файлы: (путь, mtime в наносекундах, размер).
   Параллельно считается суммарный размер.
2. **Отпечаток** = SHA-256 от отсортированного списка выше плюс версия бинарника,
   `--prefix` и абсолютные `--dir`/`--output`. Сохранённое значение лежит в
   `~/.kubeconfig-composer/init-state.json` (`fingerprint`, `version`, `updated`).
3. **Актуально.** Отпечаток совпал и `--output` существует: печатаем `export`, выход.
4. **Порог.** Отпечаток изменился, суммарный размер больше `--max-size`, `--output`
   существует, `--refresh` не указан: предупреждение в stderr
   («kc.yaml устарел, источники весят N МБ при пороге M МБ; запустите
   `kubeconfig-composer init --refresh`»), печатаем `export` со старым файлом. Отпечаток
   не обновляется, поэтому предупреждение повторяется до явной пересборки. Если
   `--output` нет, порог не действует: первая сборка выполняется всегда.
5. **Пересборка.**
   1. Блокировка `~/.kubeconfig-composer/init.lock` без ожидания. Занята и `--output`
      существует: печатаем `export`, выход. Занята и файла нет: ждём блокировку.
   2. Читаем старый `--output` (если есть): `current-context`, `namespace` контекстов,
      набор имён сущностей.
   3. `Composer` в режиме без вопросов: `ScanDirectory` (с исключением `--output`),
      `Merge`.
   4. Если старый `current-context` есть среди смерженных контекстов, ставим его.
      Только после этого `Dedupe`: он защищает `current-context` от слияния.
   5. Для каждого контекста, который есть и в старом, и в новом конфиге и у которого
      в старом `namespace` не пуст, переносим старый `namespace`.
   6. **Пропавшие чужие записи.** Имена из старого файла, которых нет в новом и которые
      не начинаются с `<prefix>:` (при пустом `--prefix` — любые пропавшие): предупреждение
      в stderr со списком (первые 10, дальше «и ещё N») и одна копия старого файла в
      `~/.kubeconfig-composer/backups/<имя>.backup.<timestamp>` (формат как у `merge`,
      его читает `revert`). Пропавшие записи с префиксом молчат: источник удалён.
   7. Если новый конфиг совпал со старым (`configsEqual`), файл не пишем.
      Иначе запись во временный файл рядом с `--output` (права 0600) и `rename`.
   8. Сохраняем отпечаток. Печатаем `export`.

## Ошибки

Оболочка не должна ломаться. Любая ошибка идёт в stderr. Если `--output` существует,
`export` печатается всё равно, код выхода 0. Если файла нет и собрать не удалось:
stdout пуст, код выхода 1 (`KUBECONFIG` не должен указывать на несуществующий файл).
Нечитаемый источник пропускается с предупреждением, как в `merge`.

## Изменения в коде

- `cmd/init.go` — тонкая команда: флаги, вызов `initstate`, печать `export`.
- `pkg/initstate/` — `fingerprint.go` (обход и хеш), `state.go` (init-state.json),
  `lock_unix.go` (`syscall.Flock`) и `lock_other.go` (без блокировки: релизы
  включают windows, а `init` рассчитан на bash/zsh), `carry.go` (перенос
  `current-context`/`namespace`, поиск пропавших чужих записей), `run.go` (алгоритм).
- `pkg/composer`: `ScanDirectory` и `scanner.FindKubeconfigFiles` пропускают каталоги
  `cache`, `http-cache` и скрытые каталоги (`scanner.IsSkippedDir`; корень обхода не
  проверяется, потому что `~/.kube` скрытый) и возвращают файлы, отсортированные по
  пути, чтобы результат не зависел от планировщика. Это же ускоряет `merge`: на
  реальном `~/.kube` 7,9 с, из них почти всё приходится на 1,5 ГБ `cache/`.
- Запись атомарная (temp + rename) выносится в общую функцию рядом с
  `cleaner.WriteConfig`: `cleaner.WriteFileAtomic` обновляет цель, если output —
  символическая ссылка; для init добавлен `Composer.WriteOutputAtomic`, `merge`
  по-прежнему пишет через `WriteOutput`.
- Подтверждённые замеры (0,1 с на МБ источников, число файлов почти не влияет)
  обосновывают порог только по размеру.

## Тестирование

Ничто в тестах не трогает настоящие `~/.kube` и `~/.kubeconfig-composer`.

- **Unit-тесты** (`pkg/initstate`, `pkg/scanner`, `pkg/composer`): каждый тест делает
  `t.Setenv("HOME", t.TempDir())` и работает только во временных каталогах. Покрыто:
  отпечаток (стабильность, изменение mtime/размера/префикса), решение по порогу,
  перенос `current-context` и `namespace` (в том числе когда контекст исчез и когда
  дубликат схлопнулся), пропавшие чужие записи, пропуск `cache/` в сканере.
- **E2E в контейнере** (`task test:container`): `scripts/Dockerfile.test` на образе
  `golang:1.24.1-bookworm` с добавленными `zsh` и `procps`, `COPY` исходников (поэтому
  локальные файлы не монтируются и не изменяются), `.dockerignore` исключает
  `.git`, `.tmp` и бинарник; в `.gitignore` для `scripts/Dockerfile.test` добавлено
  исключение `!scripts/Dockerfile.test`. Внутри запускаются Go-тесты в `e2e/`
  (build tag `e2e`) и `scripts/init_shell_test.sh`; на фикстурах в `$HOME` контейнера они
  проверяют:
  1. первый запуск создаёт `kc.yaml` и печатает `export`; `bash -c 'eval "$(...)"'` и
     `zsh -c ...` выставляют `KUBECONFIG`;
  2. повторный запуск без изменений не меняет mtime `kc.yaml`;
  3. добавление и удаление источника отражаются в контекстах;
  4. `current-context` и `namespace`, изменённые в `kc.yaml` вручную, переживают
     пересборку;
  5. файл больше `--max-size`: предупреждение, старый `export`, `kc.yaml` не изменён;
     с `--refresh` пересобирается;
  6. чужая запись в `kc.yaml`: предупреждение и бэкап в `backups/`;
  7. 10 параллельных `init`: итоговый `kc.yaml` валиден;
  8. каталог `cache/` с 10 000 мусорных файлов не замедляет второй запуск и не
     парсится;
  9. нет каталога источников и нет `kc.yaml`: пустой stdout, код 1; битый источник
     рядом с хорошими: предупреждение, `export`, код 0.
- `task test:container` не входит в `task check`, чтобы pre-commit не зависел от
  Docker. `task test` и `task check` остаются как есть, их unit-тесты безопасны
  локально.
